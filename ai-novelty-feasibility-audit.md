# AI Novelty & Feasibility Audit

*Prepared by Claude (Anthropic) as the AI Critique Summary required for this deliverable. v1 (2026-09-08 morning) was abstract-level search. v2 checked the two closest papers' full text and code availability directly. v3 attempted to resolve TAP's code status and got it wrong (concluded "likely absent"). v4 corrected that after the user found the repo directly. v5 (this version) is a full verification pass on every remaining literature-survey entry, done at the user's explicit request to be thorough and to apply that standard retroactively — it found a real misattribution (FoMoRL's origin) and, more importantly, found that World-Env is substantially closer prior work than any earlier version of this audit credited it as, which meaningfully narrows this project's novelty claim (see below). This is not a cosmetic update — it changes what the project should claim to contribute.

## Novelty

**This section required a real downward revision after full verification, not just a formatting pass — stated plainly rather than smoothed over.** A full-text check of World-Env (arXiv:2509.24948, code confirmed at github.com/amap-cvlab/world-env) found it is much closer prior work than earlier drafts of this audit credited it as: it trains and evaluates entirely on LIBERO with OpenVLA-OFT — this project's own chosen platform and base-model family — and its own ablation (Table 5 in the paper) already shows that adding autonomously-collected exploration data raises average LIBERO success from 68.4% to 79.8%. **This means the broad premise "does exploration data help VLA training" is no longer an open question this project can claim to be first at answering — it's already been shown, on the exact platform this project planned to use.**

What remains open, and is now the project's actual, narrower claim: World-Env's exploration data comes from an *already-imitation-trained* OpenVLA-OFT policy with Laplace-distributed action noise layered on top — not from curiosity-driven exploration, not from VLM-guided semantic scoring, and not from true from-scratch random play starting with no policy at all. So the honest research question this project can still claim is: **does the *source/guidance* of exploration data matter** — specifically, do curiosity-driven or VLM-semantic-guided exploration policies produce data that helps *more* than either undirected random play or World-Env's perturbed-competent-policy approach? This is a real, still-open, falsifiable comparison, but it is a narrower and less dramatic claim than earlier drafts of this proposal made, and the proposal document's Problem Formulation section should be read with this narrower framing in mind (a "does source-of-exploration-data matter" comparison, not a "does exploration data matter" discovery).

DLR (arXiv:2511.19528, Microsoft Research) is also closer prior work than earlier credited — it too runs on LIBERO and directly targets the same underlying concern (single-pattern RL exploration lacks diversity for pretraining), though via a different information-theoretic multi-pattern discovery mechanism rather than curiosity or VLM guidance.

SENSEI remains the closest paper on the *guided-exploration-method* side specifically (VLM-derived interestingness reward), confirmed to have no released code, evaluated on MiniHack/Robodesk/Pokémon Red rather than LIBERO. TAP (confirmed code released, see Feasibility) targets a related but distinct question (pretraining objective, not exploration policy) and already has partial LIBERO support in its own repo.

**Red-ocean risk: low-to-moderate, not zero.** Curiosity-driven RL as a broad subfield (dating to at least Pathak et al. 2017) is old and, in its classic form, fairly saturated — this project is emphatically not claiming novelty for curiosity-driven exploration in general, only for this specific intersection (VLM-guided semantic reward × real manipulation pixels/proprioception × downstream VLA fine-tuning evaluation). That intersection currently has, at most, one directly adjacent paper (SENSEI) and one thematically-related but methodologically-different paper (the random-play pretraining work) — this reads as thin/emerging rather than crowded, but the field's overall publication velocity on VLA data-efficiency and exploration methods is high (several independent papers on adjacent problems — VLA-RL, World-Env, "Discover, Learn, and Reinforce" — appeared within months of each other in 2025–2026), so a directly overlapping paper could plausibly appear before this project concludes. **This audit should be refreshed with a fresh literature check shortly before the literature-survey deliverable is finalized**, and again a few weeks before the final report.

## Feasibility

Directly checked against the two closest papers' full text, project webpage, and available code as of 2026-09-08; the rest of the plan (simulator/VLA infrastructure) is still assessed from documentation only, not a live run — that remains the main open item.

- **SENSEI: confirmed no released code.** Checked the paper's own project webpage (sites.google.com/view/sensei-paper) directly — it contains figures, result plots, and a bibtex entry, but no GitHub link or code section. This raises the actual engineering lift above the initial estimate: the project must reimplement the VLM-MOTIF reward-distillation idea (pairwise VLM preference comparisons → distilled reward model via a cross-entropy loss, per the paper's Section 2.1) from the method description, not adapt existing code. The paper does document its architecture in enough detail to make this tractable (e.g., the reward model is a small CNN + 2-layer MLP; annotation cost was $0.002–0.004/pair via the OpenAI API; reward-model training took ~20 minutes on a single V100 for their setup) — this project will need to reproduce something at that scale, adapted to LIBERO/ManiSkill observations, using an open VLM (an untested substitution for SENSEI's GPT-4/GPT-4o) instead of a paid API.
- **TAP: code and checkpoints ARE released — this reverses the previous version of this audit.** Verified directly: github.com/sjh0354/Task-Agnostic-Pretrain, matching author list, arXiv ID, and OpenReview ID. The repo is a fork of NORA with a Qwen2.5-VL-3B backbone, Apache-2.0 licensed, with training scripts for both stages and a released model zoo on Hugging Face (Stage-1-only and Stage-2-finetuned checkpoints at 8k/14k/20k episode scales, plus a pure-BC baseline). Full Stage 1 pretraining is documented as requiring a single 8×H100 node, which is out of reach for this project's compute budget — **but since checkpoints are already released, this project does not need to reproduce Stage 1 pretraining at all**; it can use a released TAP checkpoint as a reference/comparison point instead. Real constraint: TAP's backbone (Qwen2.5-VL-3B via NORA) is architecturally different from this project's chosen base VLA (SmolVLA), so a released TAP checkpoint cannot be dropped directly into this project's SmolVLA-based pipeline as one of the four training conditions — it's usable as an external comparison point in the writeup, not as a like-for-like baseline inside the same fine-tuning code.
- **TAP's repo already supports LIBERO as a Stage-2 data mix** (`experiments/libero/`, a documented `libero_10_no_noops` argument) — even though the paper's own headline numbers are on SIMPLER/real WidowX. This shrinks the "three-way transplant" novelty claim made in the previous version of this audit down to a two-way one (see Novelty section above) and is a more accurate, if less dramatic, description of the actual gap being filled.
- **LIBERO vs. ManiSkill: resolved — pick LIBERO as the primary platform.** Checked actual SmolVLA fine-tuning tooling for both. LIBERO has an official `HuggingFaceVLA/smolvla_libero` checkpoint from Hugging Face's own VLA org, a standard `lerobot/libero` dataset (273k downloads), and dozens of community fine-tunes all built on the same turnkey `lerobot-train` command — genuinely mature, low-friction tooling. ManiSkill support exists but is thin: only one comparable example found (`OpenRAL/rskill-smolvla-maniskill-franka`), wrapped in third-party packaging rather than an official HuggingFace release. More importantly, a live GitHub issue (huggingface/lerobot#2259) documents someone fine-tuning SmolVLA on a *different* non-officially-supported benchmark (RLBench) getting **0% eval success despite normal-looking training loss**, suspected to be an action/state-space convention mismatch between the benchmark and what SmolVLA expects. This is concrete evidence that off-the-beaten-path benchmarks can fail silently in exactly the hardest way to debug. **Recommendation: use LIBERO as the primary platform; treat ManiSkill only as a stretch/secondary check if time allows**, and explicitly verify the action/state-space convention (LIBERO's official recipe vs. whatever the exploration-phase logging produces) before assuming any fine-tuning run that "looks fine" actually is.
- **No physical hardware or large new data collection required** — the entire pipeline runs in simulation using each benchmark's existing bundled demonstrations for the fine-tuning phase; exploration data is self-generated by the agent.
- **Still not yet verified:** the exact wall-clock/compute cost of running a VLM-scoring loop inside a simulator's action loop at a frequency useful for shaping an RL reward — SENSEI's own reported throughput (its full RL loop ran at ~7.5–10Hz on an A100, with VLM annotation done offline in a separate batch phase, not in the online loop) suggests **the online loop may not need live VLM calls at all if this project follows SENSEI's actual design** (annotate an initial exploration dataset offline, distill a reward model, then run the RL loop against the distilled model rather than the VLM directly) — this is a meaningfully lower-risk design than what the original proposal draft implied ("prompting a VLM" as if inline/online), and the proposal text should be corrected to reflect an offline-distillation design unless there's a specific reason to need online VLM queries.
- **Compute:** a single mid-tier GPU (16–24GB class) is expected to suffice for both the base VLA and the exploration/reward loop, based on comparable published setups (e.g., VLA-RL's reported use of OpenVLA-7B on LIBERO; SENSEI's reward-model training took ~20 minutes on a single V100), but this has not been empirically confirmed against this project's actual pipeline, and a live timing test is recommended before the proposal is finalized.
- **Fallback path is well-defined and low-risk**: if the offline reward-distillation step proves too costly or the open-VLM substitution too noisy to be useful, the project can drop to a two-condition comparison (random-play vs. ICM-curiosity) that still tests the core, still-open question of whether unsupervised exploration data helps VLA fine-tuning at all — this preserves a publishable result even if the most novel (VLM-guided) condition has to be cut.

## Classification

**Promising, but narrower than any earlier version of this audit claimed — the World-Env finding is the important one to internalize.** Not confirmed blue ocean. The project's defensible contribution is no longer "exploration data helps VLA training" (World-Env already showed this, on this project's own chosen platform) but specifically **"does the source/guidance of exploration data matter"** — comparing curiosity-driven and VLM-semantic-guided exploration against undirected random play and against World-Env's perturbed-competent-policy approach. That's still a real, open, falsifiable question, but it's a comparative-methods question now, not a foundational-discovery one, and the proposal's Problem Formulation section should be read and eventually rewritten with that framing in mind before submission. Feasibility remains good (LIBERO confirmed as platform, TAP/VLA-RL/World-Env/Baby Sophia all have confirmed working code to reference or borrow infrastructure patterns from, SENSEI and DLR do not). **Process note, extended:** this project's due-diligence process improved each time it was pushed to go further — v2's SENSEI check was solid, v3's TAP check was incomplete, v4 corrected it, and this v5 full pass caught both a citation misattribution and a substantive novelty overclaim that no prior version had caught. The lesson generalizes: a single verification pass, even a careful one, is not sufficient — rereading closest-related-work papers in full after the first pass, specifically hunting for anything that undercuts the novelty claim rather than just confirming it, is what surfaced the most important correction here.
