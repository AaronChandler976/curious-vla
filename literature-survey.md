# Literature & SOTA Survey

10 papers/models published within the last 1–3 years, relevant to curiosity-driven exploration, developmental-robotics-inspired data collection, and VLA pretraining/fine-tuning sample-efficiency. Compiled 2026-09-08. **Update:** entries 1 and 3 below were re-verified by reading the full paper text (and, for entry 1, the project's own webpage) rather than the abstract alone — this changed two factual details in each, noted inline. All other entries are still abstract-level and should be similarly re-checked before the survey is finalized.

1. **SENSEI: Semantic Exploration Guided by Foundation Models to Learn Versatile World Models** — Sancaktar, Gumbsch, Zadaianchuk, Kolev, Martius. ICML 2025. [arXiv:2503.01584](https://arxiv.org/abs/2503.01584) · [project page](https://sites.google.com/view/sensei-paper) — **no code repository found on the project page as of 2026-09-08** (only figures, results, and a bibtex entry). *Closest prior work.* Distills a VLM-derived "interestingness" reward into a model-based RL exploration policy (built on DreamerV3's world-model architecture). The paper's own framing motivates this project directly: it argues prior semantic-exploration methods rely on unrealistic assumptions such as language-embedded environments or access to high-level actions. **Verified by reading the full paper:** SENSEI is evaluated on MiniHack, Robodesk, and Pokémon Red — not LIBERO or ManiSkill — and its VLM annotator is GPT-4/GPT-4o via the paid OpenAI API, not an open/local VLM. Its evaluation targets world-model learning quality and downstream RL-task performance in those environments, not VLA fine-tuning sample-efficiency. This project reuses SENSEI's reward-*distillation idea* (VLM pairwise-preference comparisons distilled into a reward model), reimplemented for a manipulation simulator, rather than adapting SENSEI's own architecture or code, since no code is available and the underlying RL architecture (DreamerV3) doesn't directly fit a VLA fine-tuning pipeline.

2. **Curiosity-Driven Exploration by Self-Supervised Prediction** — Pathak, Agrawal, Efros, Darrell. ICML 2017. [arXiv:1705.05363](https://arxiv.org/abs/1705.05363). The foundational Intrinsic Curiosity Module (ICM) formulation: prediction error as an intrinsic reward, tested with zero extrinsic reward. Used here as the classic, non-semantic exploration baseline.

3. **Learning to Move Before Learning to Do: Task-Agnostic Pretraining for VLAs (TAP)** — Shi, Wang, Yu, Ji, Gong, Qiu (Fudan University / Shanghai Innovation Institute). ICML 2026. [arXiv:2607.02466](https://arxiv.org/abs/2607.02466) · [code](https://github.com/sjh0354/Task-Agnostic-Pretrain) · [project page](https://sjh0354.github.io/task_agnostic_pretrain) · [released checkpoints](https://huggingface.co/collections/Michael0354/task-agnostic-pretraining). **Correction: code and checkpoints ARE released** — an earlier pass of this survey concluded otherwise after checking the ICML/OpenReview pages directly; the actual repo (found by the user, verified 2026-09-08) was missed by that check. Argues VLA data collection conflates "how to move" (self-supervised, no task labels) with "what to do" (needs language supervision); TAP's Stage 1 pretrains a Qwen2.5-VL-3B backbone with an Inverse Dynamics objective on unlabeled interaction data, then Stage 2 aligns it to language with a small expert-demo set. Built on top of [NORA](https://github.com/declare-lab/nora)'s codebase, evaluated primarily via SimplerEnv-OpenVLA (WidowX tasks) and real WidowX-250s hardware — but the repo's `training/datasets/` registrations and `experiments/libero/` folder show **LIBERO is already a supported data mix for Stage 2 alignment** (e.g., `libero_10_no_noops`), which is a materially better starting point for this project than initially assessed. Full Stage 1 pretraining is documented as requiring a single 8×H100 node — out of reach for this project's compute budget — but **pretrained Stage 1 and Stage 2 checkpoints at three data scales (8k/14k/20k episodes) are already released**, meaning this project can likely use a released TAP checkpoint directly as a reference/comparison baseline rather than reproducing the expensive pretraining step itself. One real constraint: TAP's backbone (Qwen2.5-VL-3B via NORA) is architecturally distinct from this project's chosen base VLA (SmolVLA) — reusing TAP's released checkpoints as a like-for-like baseline condition inside this project's own SmolVLA-based pipeline is not a drop-in operation, and should be scoped as "compare against" rather than "merge into."

4. **Foundation Models for Semantic Novelty in Reinforcement Learning (FoMoRL, origin paper)** — Gupta, Karkus, Che, Xu, Pavone (NVIDIA Research et al.). NeurIPS 2022 Workshop (FMDM). [arXiv:2211.04878](https://arxiv.org/abs/2211.04878). **Correction: this project's earlier survey entry misattributed FoMoRL's origin to a 2024 follow-up paper.** This is the actual originating paper — it proposes using raw CLIP embeddings (no fine-tuning) as an intrinsic exploration reward, and is explicitly cited as the source by the follow-up paper below ("This work builds on FoMoRL... Gupta et al. [2022]"). No code repository located for this paper in this search.

4b. **Fostering Intrinsic Motivation in Reinforcement Learning with Pretrained Foundation Models** — Andres, Del Ser. 2024. [arXiv:2410.07404](https://arxiv.org/abs/2410.07404). This is a **follow-up analysis of FoMoRL (4, above), not its origin** — it studies how the choice of state representation (raw RGB vs. encoded/compact) affects FoMoRL's and RIDE's exploration performance in MiniGrid. No code repository located for this paper either.

5. **VLA-RL: Towards Masterful and General Robotic Manipulation with Scalable Reinforcement Learning** — Lu, Guo, Zhang, Zhou, Jiang, Gao, Tang, Wang (Tsinghua/NTNU). 2025. [arXiv:2505.18719](https://arxiv.org/abs/2505.18719) · **code confirmed:** [github.com/GuanxingLu/vlarl](https://github.com/GuanxingLu/vlarl) (linked directly in the paper's own header; actively maintained). Online RL fine-tuning framework for pretrained VLAs on LIBERO, using a VLM-based process reward model for sparse-reward shaping. Not an exploration method per se (it fine-tunes on task-specific reward), but shares this project's LIBERO/OpenVLA-7B infrastructure and its use of VLM-derived reward signals, making it a useful implementation reference with working code.

6. **World-Env: Leveraging World Model as a Virtual Environment for VLA Post-Training** — Xiao, Yang, Chang, Chen, Xiong, Xu, Zheng, Zhang (Sun Yat-sen University / AMap, Alibaba Group). 2025–2026. [arXiv:2509.24948](https://arxiv.org/abs/2509.24948) · **code confirmed:** [github.com/amap-cvlab/world-env](https://github.com/amap-cvlab/world-env) (stated directly in the paper). **Correction after reading the full paper: this is much closer prior work than an earlier pass of this survey credited it as.** It trains and evaluates entirely on the LIBERO benchmark with OpenVLA-OFT — the same platform and base-model family this project uses — not a different platform as previously stated. More importantly, its own ablation study (Table 5 in the paper) already shows that augmenting training with autonomously-collected exploration data raises average LIBERO success from 68.4% to 79.8%, which is close to this project's core premise. The key difference: World-Env's exploration data comes from a **already-imitation-trained OpenVLA-OFT policy with Laplace-distributed action perturbation** (uncertainty-driven noise around a competent policy's actions), not from curiosity-driven exploration, semantic/VLM-guided scoring, or true from-scratch random play. **This meaningfully narrows this project's honest novelty claim**: the broad question "does exploration data help VLA training" is now confirmed by this paper's own ablation, so this project's contribution should be reframed around the narrower, still-open question of whether the *source/guidance* of exploration data matters (curiosity-driven vs. VLM-semantic-guided vs. undirected random play vs. World-Env's perturbed-competent-policy approach) — not whether exploration data helps at all.

7. **Discover, Learn, and Reinforce: Scaling Vision-Language-Action Pretraining with Diverse RL-Generated Trajectories (DLR)** — Yang, Feng, Zhang, Wang, Zhang, Zhao, Su, Chen, Bian (Microsoft Research et al.). Nov 2025. [arXiv:2511.19528](https://arxiv.org/abs/2511.19528). **No code repository located in this search** (checked abstract, intro, and targeted queries; not confirmed absent — recheck before finalizing, per the lesson learned with TAP). Also evaluated on LIBERO. Argues human demonstrations are low-diversity because human demonstrators "naturally rely on a few efficient strategies," and uses an information-theoretic RL framework to generate multiple distinct high-success behavioral patterns per task, rather than the single pattern standard RL converges to. Directly relevant supporting evidence for this project's premise that non-demonstration data sources can meaningfully add training-data diversity — and, like World-Env, is closer prior work (same benchmark) than an earlier pass of this survey credited it as.

8. **Baby Sophia: A Developmental Approach to Self-Exploration through Self-Touch and Hand Regard** — Zarifis et al. 2025. [arXiv:2511.09727](https://arxiv.org/abs/2511.09727) · **code confirmed:** [github.com/SteliosZarifis/BabyBenchAthena2025](https://github.com/SteliosZarifis/BabyBenchAthena2025) (stated directly in the paper). An RL agent that learns infant-like self-touch and hand-regard behaviors purely from intrinsic rewards in the BabyBench simulator, with curriculum learning from single- to dual-hand coordination. Provides the direct developmental-psychology grounding for this project's framing, and a concrete precedent for "purely curiosity-based signals... driving coordinated multimodal learning" with no external supervision — though confined to body self-exploration rather than object manipulation.

9. **BabyBench: A Multimodal Benchmark of Infant Behaviors for Developmental AI** — López, Marcel, Hinaut, Triesch, Hoffmann. 2025. The simulation environment/benchmark underlying Baby Sophia, itself built on the **MIMo** infant simulation platform. **Code confirmed:** [github.com/trieschlab/MIMo](https://github.com/trieschlab/MIMo) — actively maintained (a "MIMo v2" update, adding a growing body model and updated third-party library compatibility, was published Sept 2025). Cited here as the infrastructure reference for the developmental-robotics side of the literature, distinct from the manipulation-specific LIBERO infrastructure this project's main experiments will run on.

10. **ManiSkill** — Gu et al., ICLR 2023 (with ongoing 2024–2026 updates). [GitHub](https://github.com/haosulab/ManiSkill). GPU-parallelized manipulation simulator/benchmark (SAPIEN-based), reporting throughput around 2000 FPS on a single GPU with 16 processes; provides demonstration trajectories and pretrained-model infrastructure. Cited alongside LIBERO as one of the two candidate simulation platforms for this project's exploration-and-fine-tuning experiments — final choice to be confirmed during the reproduction phase based on which has better-documented OpenVLA/SmolVLA fine-tuning support at the time of implementation.
